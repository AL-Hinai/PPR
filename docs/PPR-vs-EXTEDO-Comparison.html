1Executive summary

This report compares PPR, the department's in-house medicine approval system, with the EXTEDO products that regulatory authorities use to receive, validate and review eCTD dossiers: EURS (desktop review system), EURSnext (its web companion, sold only to authorities) and EURSvalidator (the validation engine). It updates the first comparison (PPR-CMP-001 v0.1, 18 October 2026) after three weeks in which the project team closed most of the high-priority gaps that report identified, and adds a new side-by-side look at what each system's screens actually show (section 7).

The two remain different kinds of system, so they still overlap only in part:

EXTEDO EURS is a mature, specialised validation and dossier-review tool. By EXTEDO's account, more than 35 authorities use it, including the European Medicines Agency (EMA). EXTEDO also names Oman, Saudi Arabia, Bahrain, Qatar and the UAE among the agencies that use or recommend EURS or EURSvalidator. Its strengths are official, regularly updated validation criteria for each region (GCC included), deep document-review tools (annotation, full-text search, lifecycle navigation) and enterprise scale.

PPR is an end-to-end registration workflow system: a company portal, automated eCTD validation, assignment of specialist reviewers per CTD module, information requests, the HOD's decision, and a bilingual approval certificate. Its interface is in Arabic and English, it has an AI dossier assistant, and the department owns it.

Key finding. The balance has shifted since v0.1. PPR's validator now runs against the official ICH eCTD 3.2 DTD (checksum-verified) and implements the GCC Module 1 v1.5 criteria as explicit rules — the two items the first report flagged as most important before go-live are done in code. PPR also gained background (queued) validation, a printable short/long PDF report, a cumulative dossier view, department-wide search, an integration API and optional staff single sign-on. EXTEDO remains ahead on reach and proof: validation sets kept current across every region by the vendor, true in-PDF annotation, NeeS and eCTD 4.0 support, and years of production use at 35+ authorities including the EMA. PPR remains the only one of the two that runs the whole registration case — company portal, validation, specialist review, decision and certificate — in one system.

What is not yet done. PPR's validation criteria have not been independently checked against a real reference validator: the benchmark procedure is written (docs/validation_benchmark.md) and the tooling exists, but the department has no EURSvalidator evaluation licence to run it against, so this has not been executed. The new system-validation documentation (URS, risk assessment, IQ/OQ/PQ protocol) is drafted and every requirement is traced to an automated test, but qualification execution and the HOD/QA/IT sign-off have not happened. The GCC regional DTD PPR validates against is still transcribed from the published specification text, because SFDA does not distribute the file itself.

Recommendation (section 10, unchanged in substance). Keep PPR as the registration and workflow system. The two most important remaining steps are to run the validation benchmark against EURSvalidator (or another reference validator) and to execute and sign off the qualification protocol, before go-live. If budget allows, an integration in which PPR manages the case and calls an EXTEDO validator or review tool remains a viable fallback if the benchmark turns up material gaps.

2Scope, method and sources

What was compared

PPR: the code in the project repository as of 21 October 2026, including uncommitted work in progress at the time of writing. This update reviewed the README, data models, validation rules (apps/validation/), workflow, tests, and the new validation documentation set in docs/validation/ (URS, risk assessment, IQ/OQ/PQ protocol, traceability matrix) and docs/validation_benchmark.md.

EXTEDO: the products offered to regulatory authorities (EURS, EURSnext, EURSvalidator), plus eCTDmanager where the applicant side is relevant. The wider EXTEDOpulse RIM suite (registration, safety, quality and document hubs) is mentioned only where it fills a gap. This update re-checked EXTEDO's current public pages; their structure has changed since v0.1 under EXTEDO's "a Cormeo brand" refresh, but the products and their described capabilities have not.

Method and limitations

  • EXTEDO was assessed from public material only: product information sheets, EXTEDO web pages and announcements, and the EMA eSubmission page. No EXTEDO software was installed or tested, and no pricing was available. This has not changed since v0.1.
  • Most EXTEDO claims come from the vendor. Customer counts differ between sources (25, 30 and 35+ authorities). They are quoted as EXTEDO's own claims.
  • "Not stated" in this report means that the feature was not described in the material reviewed. It does not mean that EXTEDO lacks it. These points should be confirmed with the vendor.
  • PPR is a proof of concept. Statements about PPR describe what is in the code and its tests, not what has been proven in a production deployment. Where a PPR claim is backed by an automated test or a specific file, this report names it so a reader can verify it directly.
  • New in this version: section 7 places real PPR screenshots (captured 21 October 2026 from the running application with demonstration data) next to EXTEDO material. EXTEDO's current marketing pages carry no embedded screenshots of the live product; where a real vendor screenshot could not be obtained, the EXTEDO side is shown as a short, sourced description from vendor material instead of an image — this is marked clearly on each pair and is not a simulated or reconstructed screenshot.

6eCTD technical validation in depth

Technical validation was the HOD's core requirement, so it is compared in more detail. Both systems follow the same principle as the FDA and EMA: an automated technical check must pass before scientific review starts.

PPR validation rules

LayerRulesWhat is checked
1. XML schemaSCH-01 to SCH-04, GCC-01 to GCC-02index.xml exists, is well-formed and is valid against the official ICH eCTD 3.2 DTD; the regional Module 1 XML exists, is well-formed and its root is gc:gc-backbone.
2. Business rulesBR-01 to BR-10, GCC-03 to GCC-09Sequence numbering; index-md5.txt; every leaf points to an existing file with a matching MD5; no unreferenced files; required modules for the application type; lifecycle operations resolve to earlier accepted sequences; ICH file naming and path length; the GCC envelope (receiving agency, submission type and unit, related sequences) and the required Module 1 documents for Oman, including Arabic and English leaflets.
3. File complianceFC-00 to FC-08Safe ZIP; accepted file formats (DOCX only in Module 1); PDFs not password-protected; PDF version 1.4–1.7; no JavaScript or launch actions; embedded fonts (warning); size limit; no empty files; searchable text rather than scanned images (warning).

How this compares with EURSvalidator

Where PPR is now on par

  • The official ICH eCTD 3.2 DTD, checksum-verified against the published file (was a reference copy in v0.1)
  • The GCC Module 1 v1.5 criteria implemented as rules: regional structure, envelope fields, submission type and unit, required Module 1 documents
  • Checksums of the backbone and of every leaf
  • Broken references and unreferenced files
  • Lifecycle operations against earlier sequences
  • PDF security, version, JavaScript and fonts
  • File naming and path-length rules
  • Clear separation of errors and warnings

Where EURSvalidator still goes further

  • Validation sets kept current with every specification change, in cooperation with authorities, across every region EXTEDO supports — not only the GCC
  • Automatic selection of the validation set and DTD across those regions
  • NeeS, and actual preparation for eCTD 4.0 (PPR only detects and refuses an eCTD 4.0 package)
  • PDF reports that auto-save and can be emailed directly from the tool
  • The GCC regional DTD itself: EXTEDO's is the authority-distributed file; PPR's is still transcribed from the specification text, because SFDA does not publish the file
  • Years of production use and, by EXTEDO's account, independent validation at 35+ authorities
Practical risk, updated. PPR's validation criteria are now aligned with the published GCC Module 1 v1.5 specification and the official ICH DTD — the design gap from v0.1 is closed. What remains is confirmation: this alignment has not been independently checked against EURSvalidator or another reference validator on the same dossiers. The benchmark procedure and tooling are ready (docs/validation_benchmark.md, manage.py benchmark_validation, automated regression tests in apps/validation/benchmark.py), but the department has no EURSvalidator evaluation licence to run it against, so PQ-02 in the qualification protocol is still open. GCC applicants typically validate their sequences with EXTEDO tools before submitting; until the benchmark runs, there remains a residual chance that a dossier which passed the applicant's check could fail in PPR, or the reverse. This is now the single most important step before go-live.

8Strengths and weaknesses

PPR · strengths

  • Covers the complete case, from application to certificate, in one system
  • Validates against the official ICH DTD and the GCC Module 1 v1.5 criteria, not a reference copy
  • Review by specialists per CTD module, with a lead reviewer and automatic assignment by workload
  • Arabic and English, built for the department's own process
  • AI assistant that answers from the dossier and cites page references
  • Full validation documentation pack drafted, every requirement traced to an automated test
  • Background validation queue, department-wide search, printable PDF reports, staff SSO and a read-only API added since the first comparison
  • Owned by the department: no licence fees, and it can be changed quickly
  • Web-only, so there is no client software to install

PPR · weaknesses

  • Validation criteria are implemented but not yet benchmarked against a live reference validator — no EURSvalidator licence to test against
  • The GCC regional DTD is still transcribed from the published specification, not SFDA's own distributed file
  • Qualification protocol (IQ/OQ/PQ) and risk assessment are drafted but not yet executed or signed off
  • No true in-PDF annotation — review notes are linked to a page, not drawn on the document itself
  • Still a single web application; a background queue was added, but there is no distributed/multi-instance deployment
  • No eCTD 4.0 or NeeS support (eCTD 4.0 is now detected and refused cleanly, not silently mishandled)
  • Relies on a small team for support

EXTEDO · strengths

  • Validation sets aligned with authorities, covering the GCC and kept current by the vendor, across every region it supports
  • Proven at EMA and many national authorities
  • Rich review tools: true annotation, highlighting and hyperlinking of PDFs; full-text search; lifecycle navigation
  • Enterprise features: API, Active Directory, document management integration, 400+ users
  • Vendor support, training and consulting (Agency Services)

EXTEDO · weaknesses

  • No applicant portal, case workflow, decision or certificate in EURS itself
  • Licence and subscription costs (not public), plus local partner fees
  • Mainly a Windows desktop client; full web access only through EURSnext
  • Arabic interface not mentioned
  • Customisation depends on the vendor
  • No public screenshots of the live product on EXTEDO's current marketing site (section 7)

The three open items (3, 9, 12) and the in-progress item (5) are the focus for the next cycle of work; of these, item 3 (the benchmark) and item 5 (qualification sign-off) are what stand between PPR and a defensible go-live decision.

Recommendation. Proceed with option A and keep option C open, same as v0.1 — but the next steps have narrowed:

  1. Run the validation benchmark against EURSvalidator or another reference validator (gap 3 / PQ-02). This is now the single highest-value remaining step: the tooling is ready, only the reference run is missing. A trial or evaluation licence could be requested from EXTEDO or its regional partner for this purpose.
  2. Execute the IQ/OQ/PQ qualification protocol in a production-like environment and obtain the HOD/QA/Ministry IT sign-off on the URS, risk assessment and qualification protocol (gap 5).
  3. Record the HOD's decision on where the dossier assistant's language model runs, and log a live-key test before relying on written answers in production (gap 9).
  4. If the benchmark shows differences that are costly to close, or dossier volumes grow beyond what PythonAnywhere can handle, move to option C and let PPR call an external validator while keeping its workflow, Arabic interface and assistant.
  5. Ask EXTEDO to confirm the points marked "Not stated" in this report, and to provide a price for a GCC validation-set subscription or evaluation licence, so the options can be compared on cost. This has not yet been done.
